# Generated types

Every `.ts` file in this directory except `index.ts` is generated by
[ts-rs](https://github.com/Aleph-Alpha/ts-rs) directly from the Rust
structs in `unitprep-api` — **do not hand-edit them**, regeneration
overwrites them wholesale.

## Why

`types/api.ts` used to hand-mirror these shapes from the Rust side by
eye. That drifted silently once already (the `output_path` field
removal broke at runtime, not at compile time). These specific types —
`UploadResponse`, `DiscoverResponse`, `ValidateResponse`,
`AnalyzeResponse`, and everything they're built from — are now
generated straight from the struct definitions, so a backend field
rename shows up as a TypeScript error here the moment you regenerate,
not as a runtime surprise later. The rest of `types/api.ts` (dedup,
tagger, and other response shapes) is still hand-mirrored the old way —
extending this to them is a separate, mechanical follow-up.

## Regenerating

After changing any of the Rust structs listed in `index.ts`'s comment
(or one of their own fields' types), run, from this repo:

```bash
npm run generate-types
```

This runs `cargo test export_bindings` in the sibling `../unitprep-api`
checkout with `TS_RS_EXPORT_DIR` pointed back at this folder — it
assumes `unitprep-api` is checked out as a sibling directory of this
repo, which is the standing assumption both repos are developed under
(see each repo's own README). Review the diff in this folder, and if a
struct's shape genuinely changed, update whatever hand-written code
(component fixtures, tests) assumed the old shape.

If you add `#[ts(export)]` to a **new** Rust struct that should be
covered here, add a line for it in `index.ts` and re-export it from
`types/api.ts` too -- both are plain TypeScript, so a missing one is a
compile error, not a silent gap.
